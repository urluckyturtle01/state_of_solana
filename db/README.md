# Database Setup & Recovery

## Files

- `schema.sql` — full PostgreSQL schema (tables, triggers, functions, indexes). Regenerated by running `db/backup_schema.sh`.
- `setup.sh` — recreates the database from scratch using `schema.sql`.
- `backup_schema.sh` — regenerates `schema.sql` from the live DB (run after any schema change).

---

## Recreate DB from scratch

```bash
bash /root/state_of_solana/db/setup.sh
```

This will:
1. Drop `trino_charts` database if it exists
2. Create a fresh `trino_charts` database
3. Apply `schema.sql` (tables, triggers, functions)
4. Re-sync all chart definitions: `python3 sync-charts-to-db.py`

After that, run the worker to re-fetch all data:
```bash
cd /root/state_of_solana && nohup python3 -B -u trino_worker.py > trino_worker.log 2>&1 &
```

---

## Backup schema (run after any DB structure change)

```bash
bash /root/state_of_solana/db/backup_schema.sh
```

---

## Key tables

| Table | Purpose |
|---|---|
| `chart_definitions` | Chart metadata + SQL query config from YAML files |
| `query_results` | Fetched data (JSONB array) per sql_hash |
| `trino_job_queue` | Job queue: backfill / incremental / full_refresh |

## Key triggers

| Trigger | On | Purpose |
|---|---|---|
| `trg_chart_insert` | INSERT on `chart_definitions` | Creates `query_results` row + queues backfill job |
| `trg_sql_change` | UPDATE sql_hash on `chart_definitions` | Clears old data + queues new backfill (deduped) |
| `trg_cleanup_orphaned` | DELETE on `chart_definitions` | Removes orphaned `query_results` rows |
